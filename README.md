# EvidenceLoop

可验证的 Agent 经验固化与后训练数据平台。核心问题：在一个可验证的工具调用环境里，什么样的经验值得写进参数，又怎样写才安全。

## 真实模型校准：目前看到的

- 第一次冒烟，Qwen3-0.6B 没有调用任何工具，直接照抄系统提示里的示例数值，写出一份"完成了"的报告。修正：去掉可抄的示例（决策 D1）。
- 修正后模型开始调用工具，但会在一轮里连发多个调用、编造还没返回的表句柄，出错后仍然声称已保存。诊断随之改为"主因 = 最早一个没有恢复的过程错误"（D2）。
- 60 道校准题上 0.6B 全部失败。其中一部分格式错误来自 harness 比生产环境的标准解析器更严，已对齐后重跑（D3）；数值容差也与分析规则对齐（D5）。
- 对齐后（env-0.1.1）：0.6B 成功 0/60，平均 2.8 轮就停下；1.7B 成功 2/60，平均 10.3 轮，基本会把流程走完。1.7B 的失败抽样显示，大量格式错误来自嵌套参数：`filter_rows` 的条件内容是对的，只是被包成了字符串（123 次）；工具调用 JSON 写错的 139 次里，136 次出在嵌套最深的 `save_draft`。很多是同一道题里原样重发同一段错误输出，不是独立失败。
- 两个模型的分桶成功率几乎全是 0，定向组 C 会退化成均匀组 B。所以基座定为 1.7B（D4），工具参数拆平，并在训练域加入步骤更少的简单档（D6），再用新题重新校准。
- 拆平之后（env-0.2.0）：1.7B 以格式错误为主因的题从 30 道降到 6 道，单位、状态、来源三项的通过率分别从 38%、43%、17% 升到 78%、85%、65%。剩下的是要研究的错误：最常见的是根本不读规则，对数据集调用 `list_versions`，从不调用 `read_protocol`，最后在报告里随手填一个规则版本；其次是过滤写错。这一轮同时改了题目构成，所以前后的差异不能全算在拆平参数上（D10）。
- 逐题看轨迹时发现验证器的一个漏洞：1.7B 的 3 道"成功"里有 2 道在报告里多填了没要求的统计量，数是编的，验证器只查了要求的那几个。修正后（D7）报告里的每个数都要对，1.7B 的成功数从 3/60 变成 1/60。同时把"回复与状态不一致"拆成虚报和没汇报：1.7B 的 46 道全是没汇报（最后一句只回了一段 JSON），没有一道虚报；0.6B 在 env-0.1.1 的 57% 则全是虚报。
- 修正后（env-0.2.1）：1.7B 成功 1/60，4B 成功 6/60，都没到 20%，按 D8 事先定好的规则，基座定为 1.7B。工具对写错的过滤条件报错后，1.7B 收到的 28 次报错里有 24 次接着改对了。4B 不再编造参数（未溯源参数 0/60），但有 14 道题走了捷径：不读规则，直接只留 ok 行。在四分之一的题上这种做法正好算对，4B 有 1 道成功就是这么来的。出题随之修正（D9）：数据里加入任何规则都不排除的有效标记，错误路径表补上"只留 ok"和"条件写反"两条。
- 同一个指标，背后的原因可以完全不同。两个模型都有 16/60 的轨迹在报告里写了工具没算出过的数：4B 主要是把题目没要求的统计量字段填成 0（33 处）；1.7B 主要是把数据预览里的原始读数抄进这些字段（23 处）。所以分析要落到逐条轨迹，不能只看汇总数。
- 冻结后的基线（gen-0.2.1，验证器 ver-0.1.6）：validation 上 0.6B、1.7B 都是 0/50，4B 是 6/50；1.7B 在 train_mining 上 1/200，39 个分桶里 38 个是 0。定向组 C 按分桶的失败率加权，所以在这个起点上和均匀组 B 拉不开。阶段三是否先加一轮预热，在开始前决定。

目前所有"成功"都来自脚本化参考策略（`execution_mode = mock`），只用来证明工程正确；模型能力只看上面这类真实模型的结果。

## 设计要点

- **检查项必须能失败。** 环境里有被禁止但可调用的 `publish_report`，有 `list_versions`，`save_draft` 不同 key 会产生重复草稿，所以越权、找错版本、重复写入都真实可达。
- **oracle 独立。** 单位换算表、统计实现、行处理都与工具分开写。
- **错误路径表一表三用。** 生成时拒掉区分度不足的题；诊断时数值命中哪条路径就高置信归因；对抗测试直接复用。
- **示范只用观测里有的信息。** 参考策略只读对话本身，测试断言它的每个版本、句柄、ID 都有来源。
- **判定与诊断分开。** 五项判定只看最终状态；回复里写什么都不改变判定，只单独报告回复是否与状态一致。

## 与规格的差异

- 诊断新增两个类别：`filter_error`（E1、E6，排除规则用错）和 `duplicate_write`（重复草稿）。
- E6 定义为"排除了无效标记但漏掉 missing 标记"，缺失读数记为 0 并带 `missing` 标记。
- `handle_expired` 注入改为"第一个派生表句柄过期"，保证正常流程一定会遇到。
- 单位 µV 在数据里写作 `uV`。
- 存储暂用 JSONL（含内容哈希），SQLite 后补。
- 工具接口拆平（D6）：规格里 `filter_rows` 收一个嵌套的 `predicate`，`save_draft` 收一个嵌套的 `report`；现在都是平铺参数，报告由环境组装。
- 训练域多了一个简单档（单位档 all_V），规格的难度维度里没有它（D6）。
- 基座从 Qwen3-0.6B 改为 Qwen3-1.7B（D4），按 D8 复核后保留 1.7B。
- 诊断新增 unsupported_number 类别（报告里有没要求、也不正确的数），回复检查分成虚报和没汇报（D7）。
- 数据里有一种任何规则都不排除的有效标记 recal；错误路径从 7 条扩到 9 条（D9）。
