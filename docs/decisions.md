# 决策记录

每条记录：看到了什么、改了什么、为什么不算"对着测试集调"。所有改动都发生在 calibration 阶段，test 划分始终密封。

## D1 系统提示去掉可抄的示例（0.1.1）

- 现象：第一次真模型冒烟，Qwen3-0.6B 5 道题全部没调用工具，直接输出报告 JSON，数值 1.234 照抄自系统提示里的格式示例。
- 改动：系统提示只保留通用规则（数值必须来自工具、不猜 ID、每次一个工具）；报告格式移到 `save_draft` 的参数说明里。
- 理由：示例值会被小模型当成答案，这是提示词设计缺陷，不是被测能力。

## D2 诊断主类别取"最早一个没有恢复的过程错误"（0.1.2）

- 现象：模型一轮内并发多个调用、猜表句柄，之后又声称保存成功；旧规则把"声称成功"排在前面，掩盖了真正的起因。
- 改动：主类别 = 过程中最早一个没有恢复的错误；没有过程错误时，按结果归因（错误路径匹配等）。no_tool_use 只在完全没有尝试调用时成立。
- 理由：诊断要指向根因，后面的症状保留在 categories 里。

## D3 解析器与 vLLM 的 Hermes 解析器对齐，draft_key 改为可选（0.1.3，环境 env-0.1.1）

- 现象：0.6B calibration 的 32 个格式错误里，8 个是缺 draft_key，8 个是 JSON 里有多余字段，3 个是最后一个调用缺结束标签。
- 改动：解析器要求 name 与对象形式的 arguments，允许多余字段，允许最后一个调用缺结束标签；JSON 本身写错仍判 schema_error，不做任何修复。draft_key 改为可选，默认 main。
- 理由：解析器不应比生产环境里服务 Qwen 的标准解析器更严，否则测的是解析器的脾气；draft_key 是我们的幂等机制，不是被测能力。

## D5 数值容差与分析规则对齐（0.1.4，生成器 gen-0.1.2，验证器 ver-0.1.3）

- 现象：分析规则写的是"结果至少保留 4 位有效数字"，而 4 位有效数字的舍入误差最多 0.05%，原来的相对容差只有 0.01%。严格按规则只保留 4 位的模型会被判数值错误。
- 改动：相对容差改为 0.1%；区分度要求改为每条错误路径至少偏离 5 倍容差（0.5%）。新增测试：4 位有效数字必须判对，偏差 1% 必须判错。
- 理由：判分标准必须接受规则允许的一切写法；同时错误路径与参考答案之间的间隔，仍然远大于合法的舍入误差。代价是部分以中位数为统计量的题会被重新生成。
- 连带修正：容差放宽后，粗略舍入的数值可能巧合地贴近某条错误路径。诊断顺序改为先看轨迹证据：最后一次 compute_statistics 的输出已经正确时，直接判为抄写错误（calculation_error），不再去匹配错误路径。

- 规格预案：最简单配置成功率仍低于 10%，改用 Qwen3-1.7B。
