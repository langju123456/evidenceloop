# 三项目人机协同排期模型

这不是把开发总工时除以三个 Agent，也不是历史工时记录。它是一个可复算的资源约束计划：

- 人只在每天两个窗口投入判断、验收、标注裁定和学习复盘；默认每天 4 小时（09:00-11:00、19:00-21:00）。
- Agent 可以全天运行，默认最多 3 个并行实施任务。
- Mac 本地模型实验只有 1 条 lane，因此模型调用不会被三个 Agent 叠加加速。
- 所有任务都按 15 分钟格推进；依赖完成后才可开始。人机任务可能并行，但一个人工窗口一次只能做一个决定。
- 日历默认每天可用，包括周末。这只是为观察“电脑 24 小时可运行”的上界；实际日历可通过改 `calendar_days_available` 改为工作日。

## 运行

```sh
python3 schedule.py --self-test
python3 schedule.py --scope interview --human-hours 4 --agent-workers 3 --out interview-4h.json
python3 schedule.py --scope complete --human-hours 8 --agent-workers 3 --out complete-8h.json
```

`tasks.json` 记录每项工作的乐观与谨慎估计。每项只占一种主要资源：

- `human` 是你必须出现的工作：完成定义、口径和标签裁定、重要回执/退化复核、最终讲解。
- `agent` 是在要求明确后可由 AI 在后台实施、测试、整理和修复的工作。它仍可能需要你在下一个决策点验收。
- `model` 是本地 Qwen/Ollama 等实验运行；它占一条 Mac 模型 lane，但不占用你的人类小时。训练附加包的 GPU 训练不是这个 lane 的可置信预测。

### 默认配置下怎样读结果

用 2026-11-23 09:00 起排、每天 4 小时人工窗口、3 个 Agent、1 个模型 lane：

|累计范围|真人参与（低-高）|Agent 主动执行（低-高）|本地模型运行（低-高）|日历交付（低-高）|
|---|---:|---:|---:|---:|
|整理已有成果|4-7 h|5-9 h|0 h|约 1.0-2.1 日历天|
|可面试联动演示|15-27 h|36-66 h|1-4.75 h|约 3.5-7.1 日历天|
|完整离线作品集|36-62 h|81-141 h|11.75-45.75 h|约 8.5-15.5 日历天|

最后一列由脚本在 2026-11-23 09:00 起算：每天 4 小时人工窗口、3 个 Agent worker、1 个本地模型 lane、每天均可运行。`elapsed_from_requested_start` 从请求排进日历的时刻起算；若请求落在午夜或人工不在线的时段，`wait_before_first_task_hours` 会单列。依赖关系比总数更重要：例如模型对照可以在 Agent 写比较页时后台跑，但人工决定“是否推进版本”要等两者都完成。

### 模型时间的可复算假设

当前 D18 的实测不是小时级：4 道公开题 × 3 方案 × 1 次，共 12 次本地调用，三个臂合计约 79 秒。它只能告诉我们当前短单步请求约数秒级，不能直接外推成 8–16 小时。

- 面试版单步对照：`12 题 × 3 方案 × 3 重复 = 108 次`；每次上限按 20–120 秒，加 15–60 分钟冷启动/重试，得到 **1.0–4.75 小时**，按 15 分钟格向上取整。
- 完整版的单步文档族对照：`24 题 × 3 方案 × 3 重复 = 216 次`；同一上限与启动预算，得到 **1.5–8.25 小时**。
- 完整版 HorizonBench 多步任务：`8 个场景 × 3 策略 × 3 重复 = 72 次`；每次按 8–30 分钟，加 30–90 分钟环境启动/重试，得到 **10.25–37.5 小时**。它与单步调用共用同一条 Mac 模型 lane，所以完整版模型占用为二者之和 **11.75–45.75 小时**。

这些数都在 `tasks.json` 的 `model_workload` 内，可改题数、方案数、重复数、每次上限和启动预算后重跑。脚本实际计算的是 `cases × variants × repeats × seconds_per_trial + warmup_seconds`，再向上取 15 分钟；输出中的 `declared_hours_reference` 仅保留原先手算区间作对照，不参与模型任务排期。它们不含 Agent 写代码、修 bug、人工读日志或外部 GPU 训练。

在这份任务图中，把 Agent worker 从 1 增至 3，不会缩短默认 4 小时人工窗口下的面试版关键路径：人类冻结题目和最终复核才是瓶颈。把人工窗口从 4 小时提高到 8 小时，则同一范围从约 3.5-7.1 日历天降到约 2.1-3.3 天。这个结论是当前依赖图的模拟结果，不是通用规律。

### 边界

- 训练附加包需要可用 GPU/权重和数据许可；本模型不假定这些已经具备，也不把 GPU 排队算进日期。
- 外部用户、第二审阅人、线上业务流量和企业数据接入均是外部等待，当前未量化。
- 当前项目已有的年报、证据、计算和回执实验被当作起点；模型没有重新估计从零建系统的工作。
- 区间是面向计划的专家判断。完成后应以每项任务留下的实际开始/结束记录更新 `tasks.json`，而不是把预测当成事实。
