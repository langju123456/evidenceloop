# D21 预注册：分析师改口后，报告保留了哪些字段？

Oracle 的服务收入和公司总收入原表都在眼前。分析师先要求 FY2024 的贡献，随后说“先挪到 FY2025”，最后说“这页改为看服务收入同比，沿用刚才定的年份”。合格结果要同时交对财年、指标、正负号和出处。这次只评修订决定；原始表单和用户话语由 Codex 编写，每种策略在最后一步调用一次真实模型。前序对话没有新增真实用户或模型回合。

## 题目和独立依据

此前的开发数据覆盖 Apple、宁德时代，上一轮留出使用 Dell、Cisco。本次在冻结前搜索原年报基准、归档与文档，未发现 Oracle 这份申报。选 Services 收入行，Cloud services and license support 另列；服务成本行亦排除。原件是 FY2025 Form 10-K 第 65 印刷页；单位百万美元。按 FY2025、2024、2023 顺序，Services 为 5,233、5,431、5,594，总收入为 57,399、52,961、49,954。[SEC 原始申报](https://www.sec.gov/Archives/edgar/data/1341439/000095017025087926/orcl-20250531.htm)

当前年服务收入减上年得到分子。同比的分母取上年服务收入，增量贡献的分母取公司总收入净变动。FY2025 的两个参考是 −198/5,431 = −3.65% 和 −198/4,438 = −4.46%；FY2024 是 −163/5,594 = −2.91% 和 −163/3,007 = −5.42%。百分比用四舍五入保留两位。源表、八份初始表单及修改消息、逐题裁定分别保存。[原件定位](../../benchmarks/report_revision/v1/source.json) · [可见输入](../../benchmarks/report_revision/v1/questions.json) · [评分专用参考](../../benchmarks/report_revision/v1/reference.json)

## 十种办法与筛选

| 做法 | 取舍 |
|---|---|
| A 只看最后一条修改，重填表单 | 实跑；便宜但可能丢失中间决定 |
| B 看完整修改历史，重填表单 | 实跑；作为有完整信息的主要对照 |
| C 看完整历史，只提交相对送审前要改的字段 | 实跑；程序合并未改字段，模型仍需认对变更对象 |
| D 用户直接编辑表单 | 减少歧义，放弃本轮自然语言交互 |
| E 关键词和正则推断财年 | 直接年份容易，撤回和代词需要新规则 |
| F 每次改口立刻持久化结构化状态 | 支持跨会话，需按次提交和验证，调用预算不同 |
| G 再用第二模型复核改动 | 可独立查错，需要额外调用 |
| H 任何改稿都让用户确认 | 降低误交风险，额外人工成本需真实试用 |
| I 收集改口动作并做 LoRA-SFT | 先判断工程基线是否有稳定残差 |
| J 训练同观察下的修订偏好对 | 需要同义表达的可靠好坏对，以及独立文档回归 |

三臂共享送审前表单、所给原表、本地同一模型与计算程序。单条修改时 A/B 的输入应完全一致；多条修改时 A 故意丢弃中间消息，因此 A/B 只用于判别历史缺失，B/C 专门比较同一可见事实下的两种输出协议。C 的字段补齐只读送审前表单，不读取参考答案。六道可计算题各验动作、年份、指标、页码、分子、分母和百分数；两道暂停题各验动作与原因，未执行计算才可通过。模型给非法参数或格式错误记失败，传输故障记未知并保留在分母。所有数值都通过既有 Decimal 工具离线执行归档决定得到。

## 首次运行与决定规则

预先冻结题目、参考、实现与协议。8 道 × 3 种策略 × 1 次，共 24 次本机推理。沿用 D20 的 Qwen3-8B 权重、Ollama 0.32.1、上下文 4096、输出上限 160、seed 23、temperature 0，不开启思考。每题轮换策略顺序，归档第一次响应和失败，不重试挑优。以 B 为工程基线。C 必须至少交对 5/6 道计算题、两道暂停均正确、无基础设施未知，且相对 B 至少修好一道确定错误、没有原已通过题退化，才推荐替换 B；平局沿用 B。各题高度相关，仅作诊断，独立人工复核数为 0。原表公开，基础模型是否见过无法验证。
