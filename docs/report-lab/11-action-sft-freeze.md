# D22 预注册 · 年报改稿的工具选择能否用真实 LoRA 改进？

D21 的可见错误发生在交给计算器的年份和指标。D22 把问题缩小到审阅台的六个合法动作。用户提出改稿，模型从两个财年各两种业务公式、用户叫停、缺证暂停中选择一项。程序照选项实际执行并核对签名和金额。即使答错的公式能算出真数字也判错。本轮能检验工具路由，检索、自由生成参数、审批和收件各有独立验收。

## 现状与十种选择

旧工具环境已有 1.7B、W25 与多种训练采样的 Kaggle LoRA 对照，见 [D12–D15](../decisions.md)。本次查了本仓可见本地及远端分支、三项目近期 chat，找到的是旧域结果、年报应用改稿、行为评测和架构文档。没有发现这份新年报留出上的已训模型。Codex 用本机缓存完整读取 Qwen3-0.6B 快照，核对 1,503,300,328 字节权重 SHA-256 与分词器；原权重采用 Apache-2.0。[官方模型卡](https://huggingface.co/Qwen/Qwen3-0.6B/tree/c1899de289a04d12100db370d81485cdf75e47ca) · [本机版本清单](../../benchmarks/report_sft/v1/model.json)

| 做法 | 本轮取舍 |
|---|---|
| A 原模型直接选动作 | 实跑，量出已有能力 |
| B 原模型加逐字段处理说明 | 实跑，测零训练的工程对照 |
| C 相同基础提示＋动作示范 LoRA | 实跑，与 A 同观察同预算，隔离权重变化 |
| D 显式执行逐次状态机 | 有业务价值，需要新状态与重放接口，单列工程实验 |
| E 同时训练所有参数 | 本机成本高，小样本下很难归因 |
| F 换 1.7B 基座 | 同时改变基座和计算预算，留给后续容量实验 |
| G 把纠错示例放到提示里 | 需另外对齐提示长度和示例检索 |
| H 同观察下做偏好训练 | 当前有正确动作，缺少经过复核的训练组偏好对 |
| I 让模型执行工具后用 GRPO 更新 | 需要多次 rollout，先验证更省资源的监督信号 |
| J 用关键词替代模型 | 可解决明确年份，撤回或只保留部分字段需另外定义规则 |

## 数据划分与核准

先按披露来源和指令模板分组。训练为 Dell、Cisco 32 题（16 种写法各用两份报表）；开发仅 Apple 6 题；新留出为腾讯和贵州茅台各 9 题，18 种另写的修改指令；Oracle 已揭盲的 8 题只报告回归。划分间检查公司、题号、话语序列和模板编号无交叉。相似的业务意图必须跨组出现以检验迁移；同一作者编写模板、语义近重复、基座预训练见过公开文档的可能性均存在。所有题目均为 Codex 写的脚本委托，按固定财报单元格给证据。没有独立用户或人工盲标。[冻结语料与参考](../../benchmarks/report_sft/v1)

腾讯取 2025 年报印刷页 8（PDF 9）的 VAS 与 The Group 收入，单位百万元。增量 50,113，自身同比以 319,168 为分母得 15.70%，增量贡献以 91,509 为分母得 54.76%。贵州茅台取 2025 年报第 107 页第 44 项第（1）表的“其他业务”收入列与“合计”收入列，单位元。分项收入从 287,314,224.32 降到 63,517,327.14。同比为 −77.89%，占全公司营业收入净减少额的比例为正 10.86%。冻结表存金额、单位、页号与原 PDF 摘要。两张留出表只有两期，因此不能计算 FY2024 的同比或贡献。该边界用专门题验收；留出中的计算成功不证明能选对所有四个年份/指标组合。

训练、开发和留出执行时共享给定表格、菜单与完整改稿消息。每个策略每题一次前向，在 A–F 六个合法下一 token 中取最大 logit，得分以整项动作和原表独立参考数字同时正确为准。暂停还要给对原因。另存不受菜单约束时全词表第一 token 的命中数。固定菜单顺序；字母先验可能影响结果。记录真实输入 token、六项 logit、全词表首 token 和计算回执。基础设施失败保留原始采集文件，缺格不下完整结论。

## 训练预算和判定

使用同一 Qwen3-0.6B 权重、MLX 0.32.3 / mlx-lm 0.32.0 / Transformers 5.18.0。三臂均禁用 thinking，输入上限 512 token，输出一个动作，采用贪心。B 多出一段固定处理说明。C 与 A 的分词输入相同。LoRA 使用最后四层的 q、v 投影，秩 4、MLX scale 8、dropout 0。冻结全部原参数，只对正确下一 token 做全词表交叉熵。Adam 学习率 0.0002，种子 23，单条批量，完整训练两轮共 64 步、64 个监督 token。仅取末步，无开发集调参或早停。训练后从磁盘**重新加载适配器**，再跑开发、留出与 Oracle 回归。仓库保留可加载的低秩矩阵、来源和哈希，电耗未测、外部调用费为零，不用共机时长评价速度。

采用候选的诊断门槛预先定义为：18 道新留出上 C 比 A、B 各至少多对两题；两家公司相对任一对照的核准数均不下降；原已正确的暂停不能误放为计算；Oracle 回归的总核准数不低于 A。否则保留工程对照并记录退化。锁测只有两家、单种子；达标也只支持扩大复验。另报逐题修复/退化和旧域遗忘未测。实验由 Codex 代为实施。
