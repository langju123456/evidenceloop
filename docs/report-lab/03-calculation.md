# 模型能写出正确分子和分母，却给分析师一个错百分比

D18，Codex 于运行前制定。问题来自 D17 两条真实响应，均写出 12989 与 25126，却没有算出 51.70%。目标是让分析师拿到可复算的百分比，并检验是否仍选错指标或年份。Apple 同一公开表的两个财年 × 两种问题，共 4 个公开开发委托。独立预定参考答案依次为 13.51%、51.70%、12.87%、141.54%，核对来源为 FY2025 10-K 的 Products and Services Performance，第 26 页。人工转录的三个年度金额相同，工具不接触 gold。分组同模型、同表、同次数、相同推理上限；工具计算耗时另记。

| 从用户出发的做法 | 收益、代价与取舍 |
|---|---|
| A 让模型直接交一个数 | 最短路径，可能把算术或舍入做错，实跑 |
| B 指定组成分子分母的原格，程序做差和除法 | 可追踪每个操作数，模型需选对更多格子，实跑 |
| C 选一个业务计算工具及年份 | 参数少、能做输入校验，覆盖范围较窄，实跑 |
| D 给模型再思考一次 | 可能自纠，多一次推理，超出本轮等调用预算 |
| E 从年报直接复制已披露增速 | 快但整数精度不足，且无增量贡献率 |
| F 内置题目关键字路由 | 便宜，易被改口、负向表述或新词骗过 |
| G 让用户点选指标定义 | 明确但为已清楚请求增加一步，留给歧义交互 |
| H 先给原式再用第二模型审稿 | 有审阅痕迹，人工/模型再审成本更高 |
| I 收集错误操作数做 SFT | 适合工程改进后仍稳定选错的情况，暂缓 |
| J 对同观察下一好一坏算式做 DPO | 可比较语义相近的动作，需可靠偏好对及独立锁测，暂缓 |

输出同时保留单次模型请求/响应，执行器收到的实际动作、操作数、计算结果，以及预先人工复算的参考值。四题均要求引用 26 页。程序拒绝未知操作、非法参数和零分母。合同是一个单步计算诊断，只检验本表中的指标值和引用；完整终态由 HorizonBench 另验。两次调用增益相同优先考虑更容易揭示错分母、且能覆盖两类委托的方案，成本/延迟与参数合法性并列说明。若均能通过，不用四题宣布唯一胜者。

## 实际结果

同一 Qwen3-8B 量化版本、三种做法各四次，成功为数值和引用同时通过。A 直接给数 1/4，B 模型选单元格后本地计算 2/4，C 模型选业务公式和年份后本地计算 3/4。相对 A，C 修好 2025 贡献率和 2024 增速，保住了 2025 增速；B 也修好前两题，却把原本答对的 2025 增速算成 118.42%，因为模型用上年增量作分母。三种方法都没完成 2024 贡献率。C 选对了贡献公式，选错目标年份 2025，结果重报 51.70%，对照原表应为 141.54%。

| 模型输出方式 | 模型墙钟合计 | 输入 / 输出 token | 改善与代价 |
|---|---:|---:|---|
| 直接回答 | 19.394 秒 | 920 / 88 | 速度快，贡献率两题都错 |
| 原格表达式 | 31.975 秒 | 1072 / 159 | 工具可审计，错误分母仍会被准确执行 |
| 业务计算函数 | 27.585 秒 | 1068 / 148 | 四题里核准三题，仍需检查年份 |

各臂提示形式有意不同；相同的预算指每题调用一次、相同解码参数与上限。CPU 执行耗时见一次独立本地回放的[逐动作计时](../../reports/report-lab/calculation-timing-v1.json)，与模型响应时间分列。工具在归档模型动作上实际执行一次并留回执，未将执行结果再次送回模型。Codex 暂推荐 C 给产品侧试用：将模型选择的年份与用户委托显式对齐，再计算；未知年份、连续改口、跨公司表现需新实验。当前实例不需要权重训练来修正算术，也不代表所有模型均无需训练。开发样例已公开，不能当作锁测，未做独立用户试用。
