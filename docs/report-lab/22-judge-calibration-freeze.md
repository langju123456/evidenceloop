# D28 本地裁判模型判“回复是否如实”，和人对得上吗？（预登记）

状态：草稿。本页、两份评分标准、抽样、裁判和统计代码，在第一次裁判运行和第一条人工标注之前提交。评分标准和下面“判据”一节由用户改定后，再记一次冻结提交；测试集的每条裁判请求都带这次提交的完整 SHA。

## 要回答的问题

验证器对最终回复只做关键词匹配（`verify/verifier.py` 的 `reply_check`）：回复里出现“已保存”“保存成功”“已完成”“saved”就算声称保存了，再和终态比。换一种说法的声称它认不出；“回复说未发布，实际发布了”“回复里的数和草稿里的不一样”它也不查。

本实验问两件事：本地裁判模型按一份写下来的评分标准判“回复是否如实”，和人的判断有多一致；它比关键词规则更接近人，还是更远。

裁判的判定只进这份校准统计，不进 `task_success`，`verify/` 不改。

| 方案 | 判什么 | 本轮 |
|---|---|---|
| A 回复是否如实 | 工具环境轨迹的最终回复，三类：如实、虚报、判断不了 | 主实验，分开发集和测试集 |
| B 年报回答三态 | 仓库里现成的 26 条年报回答，三类：通过、错误、证据不足 | 同一套代码顺带走一遍，只作描述 |
| C 训练一个小裁判 | 用 LoRA 预测 task_success | 不做，等 A 有结论 |

## 样本怎么来（A）

- 来源是 `runs/<运行目录>/traces.jsonl` 和同目录的 `evals.jsonl`。这些文件不进版本库，抽样在 Mac 上做；用到的每个文件的指纹和条数记在样本目录的 `manifest.json`。
- 一条轨迹进池的条件：真实模型运行（不是脚本化参考策略）、不是运行故障、写了最终回复。没进池的条数按原因记在 manifest 里。同一模型同一道题、回复和轨迹完全相同的重跑只留一条。
- 关键词判定结果在抽样时用当前验证器的 `reply_check` 对每条轨迹重新算一遍，不直接用旧的 `evals.jsonl` 里那一栏：早期运行是用旧版验证器评的，口径不一样。`evals.jsonl` 只提供 task_success 和失败类别，放进 `key.jsonl`。
- 先切分，再抽样。按 task_id 的哈希把题分成开发侧和测试侧（比例 40:80），同一道题的所有回复都在同一侧。
- 每一侧按“模型 × 关键词判定结果（虚报／没汇报／一致）”分层，各层轮流取，直到取满。少见的层被有意多取，所以样本里虚报的比例不是轨迹池里的比例；每层在池里有多少条记在 manifest 里。
- 默认开发集 40 条、测试集 80 条；隔天重标的 20 条从测试集里同样分层取。三个数都可以用命令行参数改。
- 样本只写一次。再运行同一条命令会重新算一遍并核对指纹，对不上就停，不覆盖。

每条材料只有两段：最终回复原文；从运行记录抄出来的事实（按顺序的工具调用和成败、算出过的数、最后存下的草稿和内容、成功发布的次数）。模型名、运行目录、五项判定、关键词规则的结果都不在材料里，单独放在 `key.jsonl`，只有统计那一步读它。

## 谁标、怎么标

- 标注者一人。人与人之间的一致性这次测不了，用同一人隔天重标来代替。
- 标注表是离线 HTML（`el judge form`），由材料的两段文字生成，页面里没有模型名、程序判定和裁判输出。条目顺序按表单编号排，和分层无关；重标表的编号和顺序与第一轮不同。
- 表顶部是评分标准正文，和裁判提示词里的是同一段文字。回收的标注文件记下标注时看的是哪一版评分标准。
- 备注可以不填。进度存在浏览器里，可以分几次标。
- 顺序：先标开发集 → 在开发集上调评分标准 → 冻结 → 标测试集 → 隔一天标重标表 → 裁判跑测试集。测试集的人工标注必须在裁判运行前交齐，运行时登记它的指纹，之后改过就不能参加统计。

## 裁判怎么跑

- 通过 Ollama 的 HTTP 接口调本机已安装的模型，默认 `qwen3:8b`，可用 `--model` 换成别的已安装标签；不下载权重。
- 每条材料一次请求：temperature 0、seed 23、关闭思考、上下文 8192、输出上限 400 token，输出用 JSON schema 固定为 `points`（回复里声称做了的事）、`reason`、`verdict` 三个字段，`verdict` 只能取评分标准里的三类。
- 系统提示 = 一句固定说明 + 评分标准正文 + 输出格式；用户消息 = 材料的两段文字。提示词版本是系统提示、输出 schema 和采样参数的哈希，写进每一行结果；评分标准改一个字，版本就变。
- 每行结果保留完整请求、原始响应、模型摘要、Ollama 版本和耗时。请求失败记为传输错误，输出不是合格 JSON 或判定不在三类里记为不合格；这两种都不重试，留在分母里，统计时算作和人不一致。

## 开发集和测试集的规矩

- 开发集可以反复跑：看裁判和人在哪些条目上不一样，改评分标准或提示词，再跑。每次输出一个新文件，不覆盖。
- 测试集只跑一次。`el judge run --split test` 要求：
  1. `--freeze` 给出冻结提交的完整 SHA；评分标准、`src/evidenceloop/judge/` 下的五个模块、本页、样本的 manifest、key 和测试集条目，都必须和该提交逐字节相同。
  2. `--labels` 给出已回收且全部标完的测试集标注；它标注时看的评分标准必须是当前这一版。
  3. 样本目录里还没有 `judge-test-started.json`。运行一开始就写这个文件，第二次运行会被拒绝。
- 统计测试集时再核对一遍：每条请求必须和当前评分标准、当前样本算出来的请求完全相同，条目齐全，模型和提示词版本只有一个。
- 测试集出结果后，评分标准和提示词不再因为测试集的错例修改；要改就另抽新样本。

## 统计（`el judge agree`）

- 人对裁判、人对关键词规则：一致率、Cohen's kappa、混淆矩阵（行是人）。
- kappa 的 95% 区间：按 task_id 整簇重抽 10000 次（种子 0）取百分位。簇少于 10 个不给区间。
- 裁判对关键词规则：在同一批条目上看谁和人一致，对不一致的两格做 McNemar 精确检验（双侧），并给出一致率之差的自助区间。
- 标注者自己：重标的 20 条上，第一轮和第二轮的一致率、kappa 和混淆矩阵。
- 人没标的条目不进统计，单独计数。
- 测试集在裁判运行之前只允许看重标一致性，不提前比较人和关键词规则。

80 条时 kappa 的 95% 区间半宽大约 ±0.16（按一致率 0.85、偶然一致 0.5 的近似公式估的），所以这次只能分辨大的差距。

## 判据（草稿，冻结前由用户定）

1. 先看标注本身：重标的 20 条里，前后两次不一样的超过 3 条，就说明评分标准或标注还不稳，这一轮只报告数字，不对裁判下结论。
2. 裁判可以用来筛查虚报：测试集上人对裁判的 kappa 不低于 0.6，区间下界不低于 0.4；并且“人判虚报、裁判判如实”的条数不多于关键词规则的同一格。
3. 裁判比关键词规则更接近人：裁判的一致率更高，且 McNemar 精确检验 p < 0.05。不满足就记“分不出”。
4. 不合格输出和传输错误合计超过 4 条（5%），按工程问题记录，不下模型结论。

## 方案 B：年报回答三态

样本是仓库里现成的全部 26 条：`benchmarks/report_dev/v1` 的 14 条观察（2 条真实模型、12 条脚本构造）和 D17 归档的 12 条真实 Qwen3-8B 回复，已冻结在 `benchmarks/judge_calib/v1/annual/`。材料是问题、回答、引用页或模型当时看到的摘录，加上核对过的原表摘录。对照的程序判定：前 14 条用 `value_pages` 评分，后 12 条用 D17 的归档判定；前 14 条另有开发标注。

26 条不切分，没有开发集，所以评分标准写定后只跑一次，规矩同测试集（`--split all`）。只有 5 道题，按题重抽不给区间；被评的回复有 14 条来自和裁判同族的 Qwen3-8B。B 的结果只作描述，不单独下结论。

## 已知局限

- 标注者只有一人，重标只能说明同一个人前后是否稳定。
- 分层用了关键词规则的结果，样本里各类的比例是人为拉平的；这里的一致率不能直接当成全部轨迹上的一致率。
- 工具环境是模拟的，回复的写法由少数几个 Qwen3 尺寸决定，结论不外推到别的模型和别的任务。
- 裁判看到的事实是程序从运行记录里摘出来的，摘录本身漏了什么，人和裁判都看不到。

## 在 Mac 上按顺序执行

每步一条命令，标注在两步之间手工完成。输出在 `reports/judge-calib/v1/`。

```sh
bash scripts/mac_judge.sh sample                      # 抽样并冻结，然后提交 benchmarks/judge_calib/v1/reply
bash scripts/mac_judge.sh form dev                    # 生成开发集标注表，浏览器里标完后导出 JSON
bash scripts/mac_judge.sh labels dev ~/Downloads/judge-labels-dev.json
bash scripts/mac_judge.sh smoke                       # 裁判只跑开发集前 3 条，确认接口和输出格式
bash scripts/mac_judge.sh dev                         # 裁判跑开发集并统计；改评分标准后可再跑
# 评分标准和判据改定后提交，记下完整提交号 FREEZE
bash scripts/mac_judge.sh form test
bash scripts/mac_judge.sh labels test ~/Downloads/judge-labels-test.json
bash scripts/mac_judge.sh form retest                 # 隔一天再标
bash scripts/mac_judge.sh labels retest ~/Downloads/judge-labels-retest.json
bash scripts/mac_judge.sh retest                      # 只看重标一致性
bash scripts/mac_judge.sh test "$FREEZE"              # 只能跑一次
bash scripts/mac_judge.sh annual-form
bash scripts/mac_judge.sh annual-labels ~/Downloads/judge-labels-all.json
bash scripts/mac_judge.sh annual "$FREEZE"            # 只能跑一次
```
