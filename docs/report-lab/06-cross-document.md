## 入选与排除

D18 在 Apple 单份原表上开发，测试三种策略。D20 预先选择 Dell 和 Cisco，二者独立披露 Services 和合并总收入，且 FY2025 的同一张收入表列出 FY2025、FY2024、FY2023 三年可复算金额。原表中的 Services 类别由发行人界定；试验比较各自年度内的比例，不比较两家公司服务业务的绝对水平。核过 EvidenceLoop 基线 6a1adcd 的年报开发数据、报告及归档，未发现这两份申报被用于本项目策略开发。公开申报可能出现在基础模型预训练中；同一种任务模板有意从开发阶段保留，以隔离跨文档迁移。

## 先锁定八题怎样算对

同比 = 100 × 服务收入净变动 ÷ 上年服务收入；贡献 = 100 × 服务收入净变动 ÷ 总收入净变动。独立核验先读原始申报并直接复算，参考值单独保存；封装进模型输入的只有问题、摘录、输出约定和当前做法允许的工具参数。单题通过要求百分比数值与 ROUND_HALF_UP 两位的参考相等（允许等价末尾零），并引用该原表印刷页。错值、错页、参数/JSON 不合法归失败；传输错误归未知，继续占分母。每格只收首次响应，不补采覆盖错误。

## 十种交付办法与本次三项实跑

| 办法 | 为什么纳入或留待后续 |
|---|---|
| A 模型直接给数和页 | 实跑。最接近普通回答，保留可比较基线 |
| B 模型交出分子、分母格子，程序计算 | 实跑。可定位具体选错的格子 |
| C 模型选业务公式、业务和财年，程序计算 | 实跑。D18 暂定候选，检验跨公司退化 |
| D 从年报照抄披露的整数增速 | 不能交付自行复算的两位数或增量贡献 |
| E 交给分析师选指标再算 | 最终可解释，但需额外人工步骤 |
| F 用中文模板精准匹配意图和财年 | 可做廉价基线，需另测改口、多年和否定表达 |
| G 执行前用独立解析器校验年份 | 直接针对 D18 失效点；首次留出用于评估原策略，后续新公司测修正 |
| H 让第二模型再审一次动作 | 增加调用预算，且需独立校准 |
| I 用确认的正确工具动作做 SFT | 需要跨文档稳定出现的动作错和独立训练资料 |
| J 用同一观察下的一好一差动作做 DPO | 需可靠偏好对，以及 SFT 之后仍存在的可复现错误 |

## 预算、判据和复验

同一题给 A/B/C 相同原表和用户问题，动作说明沿用 D18；页码、真实表名、总收入行标签按发行人替换。每格本地 Qwen3-8B 一次，8 题 × 3 格，共 24 次。模型完整摘要和 Ollama 版本见协议，参数上下文 4096、输出上限 160、temperature 0、seed 23、关闭思考、JSON 输出。按题轮换顺序，以减少固定出场顺序的影响。工具在原始动作归档后以相同的 Decimal 计算器实际执行；网络等待和真实推理时延一并记录，单次墙钟仅作描述。采集串行，避开 HorizonBench 的模型批次。

预先推荐条件：C 至少答对 6/8，两家公司分别至少 2/4；相较 A 至少修好一题且没有已通过题退化；两道负贡献题都须通过，C 不能有基础设施未知。本门槛是进入更大试点的工程判断。八题仅两个文档家族，报告逐题与每家分数、token 和总耗时，不计算生产成功率、显著性或稳定延迟。直接回答错数时只归因于可见输出；错误内部算法不作推断。根据动作记录区分指标、年份、取格、页码和工具执行错误，再判断是否需训练。
