# D19 四个复核名额应先看哪些回答？

发布负责人每天只能请复核者读几题，既想发现错误放行，也要知道抽到的是哪些任务。比较前固定 D16 的 14 条观察，每种办法取 4 条，种子为 report-review-v1，不调用模型。先排队，最后才揭开 Codex 开发标注。记录覆盖题型、归档模型条数、已知错误和待定数；后两项只能用于回顾这批选择。此处的模拟预算是四条，实际分钟与人工复核准确率需真实审核者提供。

| 可选做法 | 实际取舍 |
|---|---|
| 按录入顺序 | 工作量小，容易被成批入库的同类题占满；实跑 |
| 全库按种子打乱 | 可复现，不保证覆盖罕见题型；实跑 |
| 按问题分层轮取 | 在定额内多覆盖不同业务问题，不估计自然流量中的发生率；实跑 |
| 先看自动评分规则互相冲突的 | 有助查错放，选择偏差大；实跑 |
| 全量逐题盲评 | 小开发集成本可接受，随样本数线性增加 |
| 按线上任务流量比例抽样 | 适合估整体质量，还没有真实流量分布 |
| 固定保留一半高风险金额题 | 可防重大财务差错，严重性和损失阈值需业务确认 |
| 优先新版本相对旧版有翻转的题 | 查回归效率高，共同犯错的两版容易漏掉 |
| 优先抽检证据读取超时 | 衡量未知处理，覆盖不到正常读表中的口径问题 |
| 双人独立标注、异议交第三人裁决 | 单题证据强，占用更多审核人，当前没有实际参与者 |

初期建议将全量公开开发题交给复核者，若只能看四条，普通题型覆盖和故障排查分开报告。此选择由 Codex 推荐，复核者仍可对每条给出不同于开发标注的判定及理由。

## 同预算实测

| 选择方法 | 覆盖不同问题 | 归档模型回答 | 开发标注为对／错／待定 |
|---|---:|---:|---|
| 录入顺序 | 2 | 2 | 3／1／0 |
| 固定打乱 | 4 | 1 | 3／1／0 |
| 按问题轮取 | 4 | 1 | 3／1／0 |
| 规则分歧优先 | 2 | 1 | 0／3／1 |

分歧优先命中了宁德时代历史季度错答，也漏掉了所有正确例。按题轮取覆盖四个问题，但漏掉了这条实际错答。完整版只有 14 条，首次复核推荐全量。后续只有四个名额时，按目的选对应名单，同规则与另一种规则都判对的样本仍需随机抽检。目前真实独立复核数为 **0**。[每种方法实际选中的观察及结果](../../reports/report-lab/review-sampling-v1.json)

## 怎样复核和回收

[公开练习表](../../reports/report-lab/blind-review.html)可演练填写流程，稳定编号可由公开运行编号推回。正式复核时由负责人生成本次专用的随机编号映射，只把该映射生成的 HTML 与两份原年报交给复核者。随机编号阻断编号关联；已看过这些公开题的人仍可能从答案正文认出原判定。文件包含公开题、待判答案、引用页、当时的证据读取状态和独立的原表摘录。模型名称、旧判定、对错提示性的运行编号都从表单中移除。手工记录：填复核者代号，选通过、错误或证据不足，写依据，导出 JSON。表单允许先交部分，未填的条目计为 pending。关闭前请导出，浏览器不保存草稿。已公开的开发题及回执可能被看到，盲评依赖复核者未提前读过结果。

在仓库根离线复验或导入实际回收的文件：

```sh
PYTHONPATH=src python3 -m evidenceloop.cli report sample-review --budget 4
# 将路径放在负责人自己的目录，保留映射供回收，不随表单发送
PYTHONPATH=src python3 -m evidenceloop.cli report review-key --out /path/to/private-round1.json
PYTHONPATH=src python3 -m evidenceloop.cli report blind-review --out /path/to/round1.html --key-file /path/to/private-round1.json
PYTHONPATH=src python3 -m evidenceloop.cli report reconcile-review --submission /path/to/report-review.json --key-file /path/to/private-round1.json
```

评测入口校验表单版本、样本指纹、完整且无重复的条目标识、判定与依据。原始开发标注不会被回写。返回逐条差异、已评数、待评数和一致数，自填代号无法认证人的身份。负责人须确认审核者身份与独立性，异议回原表裁决并另外冻结修订版后，才能报告双人校准。数据改版应重新发包。自动脚本填表只验证传输链路。
