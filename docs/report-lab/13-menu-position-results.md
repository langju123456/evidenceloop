# D23：菜单位置扰动诊断

2026-11-24，冻结18条委托（9组允许/暂停对照）、2种菜单排列、base/lora两臂，共72次首答。沿用D22权重与六个合法字母的首token约束选择；没有重新训练、选种子或重试后择优。实际模型运行8.1652秒；模型调用前校验基础权重、适配器、输入与协议摘要。模型只接收messages，不接收金标。

| 指标 | base | LoRA |
|---|---:|---:|
| 语义动作正确 | 10/36 | 7/36 |
| 换菜单后仍选择相同语义（成对） | 1/18 | 0/18 |
| 工具拦截无效计算 | 0/36 | 6/36 |
| 执行后产生错误结果 | 7/36 | 18/36 |

逐题/菜单配对：LoRA修好4项、损坏7项。JSON中 `menu_position_consistent` 统计的是两种菜单下的行数（2/36、0/36），上表按配对换算，不混用分母。能得到相同语义不等于语义正确；本轮也不能仅凭位置敏感证明训练失败的唯一原因。

决定：继续拒绝采用该适配器。原模型也对菜单变化敏感，应在新的训练或工具接口设计之前先明确动作语义和不变性要求。18条委托复用了开发/回归来源，不视为新的文档留出集；这不是自由工具参数或多步Agent端到端训练。

后续审查发现：V1轮换了菜单，但“送审前动作”仍沿用原字母，未同时转换其对应业务含义。虽然本批委托明确覆盖了目标或叫停，这仍是额外输入变量，因此本轮不能纯粹归因于位置偏好。原72条不删除、不重写；下一版应保持初始动作语义一致后重新冻结对照。D22留出集退化及拒绝采用的结论不依赖此诊断。
