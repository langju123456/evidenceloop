**同一个 10.86%，能是正确结果，也能是应当拦下的错报。** 茅台第 05 题要求把年份换到最新一列，继续算其他业务的收入增量贡献。训练前模型暂停。适配器选 FY2025 贡献，程序实际以 −223,796,897.18 除以 −2,061,049,761.55，交对 **+10.86%**。第 09 题要求保留原稿 FY2024，所给原表只有 FY2024、FY2025 两列，计算该指标还缺 FY2023。适配器却选 FY2025 并算出相同数字。单看百分数、符号、页码或工具执行成功都会漏判。

相对原模型，修好 1 题、退化 4 题。四条退化原先都正确识别缺证。三条新动作因缺少单元格被计算器拒绝；只有茅台第 09 题实际返回了错年的数。明确叫停的两题，原模型都选错暂停原因，适配器也都未按用户要求暂停。Oracle 回归从 1/8 到 2/8，内部是修好两条、丢掉一条；旧题总数上升不能抵消新留出的退化。按全词表首 token 另算，新留出仍为 4、4、1。所有输入、候选分数、全词表首 token 与每次执行的回执可以展开。[离线逐题页](../../reports/report-lab/review.html#sft) · [机器裁定](../../reports/report-lab/action-sft-v1/results.json)

## 怎样确认适配器是真实的？

1. 先冻结公司、指令、验收、代码、训练预算与采用条件并推送，提交为 `7592787c847230094e9217aac8bb36287d274a04`。只有 Dell 和 Cisco 的 32 条训练指令进入优化器。A 与 C 的逐条模型输入完全相同。B 的额外规则清楚可见。[冻结协议](11-action-sft-freeze.md)
2. 在 Apple M4 上，以 MLX 载入原始 Qwen3-0.6B 权重。冻结原参数，只更新最后四层 q/v 投影的 16 个低秩张量，共 81,920 个参数。种子 23，训练两轮、64 次 Adam 更新、64 个监督动作 token。两轮平均训练损失分别为 2.5333、2.2141。原先为零的 B 矩阵最大绝对值达到 0.03140。记录到的训练循环耗时 9.679 秒，MLX 报告峰值内存约 1.58 GB，外部调用费为零，电耗未计。[64 步训练记录](../../reports/report-lab/action-sft-v1/training.json)
3. 训练程序退出，另一个进程分别重新加载基座、基座、基座加磁盘上的适配器。三臂各跑 32 道，共 96 次首答。329,390 字节适配器的 SHA-256 是 `2ffa83b2e74ead3f9b819907329a54728499979fd2cee9f903f193b4053777de`。原基座许可及归属随适配器列出。全部评分可以在没有 GPU 的机器上从归档重新执行。[可加载的 MLX 适配器](../../reports/report-lab/action-sft-v1/adapter) · [96 份模型记录](../../reports/report-lab/action-sft-v1/predictions.jsonl)

## 下一轮值得检验什么？

本轮在一家公司内有多个相关问题，只涉及两个新文档、一枚种子和固定菜单。原模型无条件选 F、适配器偏向 C，是观察到的行为。单凭这批结果无法区分字母位置偏好、指令分布、样本规模或模型容量的作用。下一次应在训练/开发文档上先做动作名称与菜单位置互换的小对照，给同一份原表造“允许出数／必须暂停”的成对示范，核对同义指令和用户撤回。等两个信号都能稳定区分，再另取新公司冻结复验。此次腾讯与茅台的 18 题其后仅用于回归。

当前核准的是从六个合法工具动作中选出一个，并用已给定的表格执行。训练、运行与推荐由 Codex 代为完成，独立人审为 0。尚待验证自由生成工具参数、完整报告交付、真实使用中的错报率、其他工具域遗忘以及换种子后的稳定性。旧工具域的 Kaggle 九个 LoRA 和上一轮 Oracle 的 8B 结果各自保留原口径，此处严格比较同一 0.6B 模型的三个条件。

## D22 后续：先分开业务动作与菜单位置

已完成菜单位置诊断的72次首答，详见[结果及局限](13-menu-position-results.md)。协议为9组同一业务情境的“允许出数／必须暂停”委托，共18条；每条以两种菜单给原模型、已归档适配器各一次。先将字母按当次菜单反解为业务动作再评分；报告动作正确、一致性、工具拦截、最终错报与配对修好/退化。确定性业务路由仅可作参考，不计作模型收益。

推理前必须先写出 `manifest.json`，其中含样本、菜单、基础权重和归档适配器哈希；不重训、不挑种子。此诊断不能证明自由工具参数、完整 Agent 或训练有效，只回答菜单位置是否可能解释已观察到的选择。另导出三个评测划分的 29 条真实适配器失败和离线人工复核页；其人工标注固定为 0，机器重放和 Codex 生成的字段均不冒充独立专家结论。

```sh
export PYTHONPATH=src
python3 -m evidenceloop.cli report action-sft-position prepare --out reports/report-lab/action-sft-position-v1
python3 -m evidenceloop.cli report action-sft-position export-legacy-failures --out reports/report-lab/action-sft-position-v1-review
```

模型通道由协调线程显式交接后，运行器只能向 `manifest.json` 的 72 个单元各写入一条 `attempt: 1` 的首答记录；再离线评分：

```sh
python3 -m evidenceloop.cli report action-sft-position score --out reports/report-lab/action-sft-position-v1 --responses first-responses.jsonl
```
