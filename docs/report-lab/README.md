# 年报报告评测实验室

给分析师交付可核验、能局部修订、能在下一期复用的报告。EvidenceLoop 的使用者是发布新版本的人：打开同一份委托的两次运行，看到哪些结论修好、哪些退化，以及新增成本。读者可从此页恢复工作。

| 责任人 | 权威记录 |
|---|---|
| ForgeFlow | 实际业务任务、权限、工具执行、稿件修订、审批与交付 |
| HorizonBench | 场景快照、故障注入、原动作回放和独立终态断言 |
| EvidenceLoop | 版本化样本、标注与复核、评测校准、配对比较、训练及回归 |

交换时保留协议版本、case_id、run_id、尝试编号、数据及模型版本、可观察工具动作、产物引用/digest、分项断言与终态、用时及成本。缺失填 null；摘要中的事件计数不充当完整工具轨迹。保存原始来源与数据加工谱系。未经复核的标签注明作者。未来引入审批/收件回执时，以 HorizonBench 的独立读取为准。

| 成果 | 验收 | 当前进度 |
|---|---|---|
| 能解释一次真实错答 | 宁德时代全年与季度、Apple FY25 增速与贡献都可回到原表；真实成功例与错例一并报告 | [D16 比较方案](01-scoring.md) |
| 能判下一版值不值 | 固定模型、题目、预算；隔离表头缺失、证据选择与选错分母。逐题看前后轨迹、原表和未知项 | 后续实验 |
| 能评价整份报告 | 比较初稿→修订→合法批准→实际收件；会话清空、并行修改和回执丢失五类场景由 HorizonBench 验证 | 等版本化回执 |
| 能量化再次使用的价值 | 换期复用模板后核对新证据、遗留旧数、人工复核耗时；个人试用与独立试用分开 | 等真实试用 |
| 能决定是否训练 | 同一输入下仍错才考虑 LoRA-SFT；持续可复核的同观察正负对再做 DPO，GRPO 待可靠环境奖励与资源。对照强工具基线，查遗忘、种子差、token 与 GPU 时 | 已有旧域 LoRA 对照，年报训练尚无结论 |

公开开发案例不进锁测，不报告生产成功率。后续按公司和重复披露文档族分组切分，先切分再扩写，双标与盲评交由独立人员；程序判硬要求，rubric/LLM judge 只评开放项并校准。跨版本报告全部委托数、修好和退化、未知、严重错误、延迟和每成功交付成本。拟以 24 份完整委托试点；效应区间按文档族重抽，未达到样本量不作稳定收益判断。数据标明历史真实模型、当前真实模型、独立环境回执、脚本构造、模拟故障或实际试用。为本项目做出的选择由 Codex 代为试验、记录和推荐，独立复核及用户亲自决策另记。

## 从仓库根复验 D16

```sh
PYTHONPATH=src python3 -m evidenceloop.cli report compare-claims
PYTHONPATH=src python3 -m evidenceloop.cli report verify-sources --pdf-dir ~/code/finreports --archive ~/code/forgeflow-desk/preparation/s5/desk-service/real-model-run.json
```

第一条只需要仓库和 Python 3.10+，输出含每题记录及输入哈希。第二条使用已持有的原始文件核对 PDF 哈希和归档回答。两份原 PDF 未重新分发。开发集收录原文件哈希、原归档提交、精选两条完整回答回执、人工转录的单元格与列头页。历史记录没有逐次模型输入，不能由此断定当时究竟是召回漏了表头还是模型忽略了它。
