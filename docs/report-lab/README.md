# 年报报告评测实验室

给分析师交付可核验、能局部修订、能在下一期复用的报告。EvidenceLoop 的使用者是发布新版本的人：打开同一份委托的两次运行，看到哪些结论修好、哪些退化，以及新增成本。读者可从此页恢复工作。

| 责任人 | 权威记录 |
|---|---|
| ForgeFlow | 实际业务任务、权限、工具执行、稿件修订、审批与交付 |
| HorizonBench | 场景快照、故障注入、原动作回放和独立终态断言 |
| EvidenceLoop | 版本化样本、标注与复核、评测校准、配对比较、训练及回归 |

交换时保留协议版本、case_id、run_id、尝试编号、数据及模型版本、可观察工具动作、产物引用/digest、分项断言与终态、用时及成本。缺失填 null；摘要中的事件计数不充当完整工具轨迹。保存原始来源与数据加工谱系。未经复核的标签注明作者。未来引入审批/收件回执时，以 HorizonBench 的独立读取为准。

公开开发案例不进锁测，不报告生产成功率。后续按公司和重复披露文档族分组切分，先切分再扩写，双标与盲评交由独立人员；程序判硬要求，rubric/LLM judge 只评开放项并校准。跨版本报告全部委托数、修好和退化、未知、严重错误、延迟和每成功交付成本。拟以 24 份完整委托试点；效应区间按文档族重抽，未达到样本量不作稳定收益判断。数据标明历史真实模型、当前真实模型、独立环境回执、脚本构造、模拟故障或实际试用。为本项目做出的选择由 Codex 代为试验、记录和推荐，独立复核及用户亲自决策另记。

## 离线逐题查看

直接用浏览器打开[逐题对照页](../../reports/report-lab/review.html)。在 GitHub 网页上先下载 HTML 到本机。它包含 24 次本机真实推理与 14 条评分观察，数值、来源、输入、原始响应和计算动作可各自展开。用页面上的文件选择器选原年报，浏览器会核对 SHA-256 后启用相应页码；文件不出本机。没有 PDF 也能核对冻结的原表摘录。页面还收录四条产品问答和十二条独立环境终态，可核对缺少回执时的漏发和重复交付。

重新生成：`PYTHONPATH=src python3 -m evidenceloop.cli report review-page --out reports/report-lab/review.html`。已用独立临时 Chrome 配置验证展开原表、关联正确 PDF、拒绝不同版本、跳转计算对照及 390 像素宽视口；外部请求和页面错误均为零。以上是脚本操作的浏览器功能验收，尚无真实用户体验测量。

## 给另一位审核者做独立判断

[盲评练习表](../../reports/report-lab/blind-review.html)可离线填写并导出。正式发放时可生成私有随机编号映射；负责人自行保管。负责人导入 JSON 后可查每条分歧、依据和未评项。[D19 复核取样与回收说明](05-review.md)包含四种选择方法在四条预算下的实测。现有标注均来自开发阶段，尚未收到真实独立复核。

## 接下来怎样做发布判断

1. **同次委托贯通。** 选择一份分析师实际会交付的现金流报告。ForgeFlow 输出初稿、修订稿、批准记录和稿件指纹，HorizonBench 按同一任务号在收件方检查版本、份数和内容。EvidenceLoop 同屏列出数字、证据、审批、收件和不可确认的项。若正确稿件已存在而读取另一份材料超时，保留已证实的交付事实，同时记录读取故障。未确认的终态不能补记成功。
2. **独立样本与校准。** 在新增公司、不同年度和不同表格布局之间，先按公司与文档家族锁定训练、开发、测试分组，再生成改写与工具轨迹。同一披露的中英版本、摘要、季度分拆、改写题归同组。对文件哈希、文本近重复和跨组答案模板做排查，并冻结数据清单、判定规则和标签作者。用人类复核开放式解释质量，记录原始分歧和裁决。若引入模型评委，先与盲评标签逐类校准，保留误放和错拒。
3. **比较下一个候选。** 优先给计算调用补年份约束，在跨公司新题与旧版同模型、相同解码预算、同题同种子比较。按完整委托计成功，列出每道修好或退化、严重错报、证据不足、耗时与每个成功件的成本。分别报告模型耗时和工具执行耗时。锁测前冻结主指标，多个候选共用一次检验族；按文档家族报告配对差及区间，有效家族太少只做描述。当前公开开发数据只支持选择下一轮候选。
4. **训练有条件进入。** 固定原表、输入和工具后，若仍反复选错年份、指标或分母，从训练组收集成功示范，先用 LoRA-SFT 学习正确的下一步动作，再与同一基座、同一工程强基线按锁定预算评测。LoRA/QLoRA 决定怎样节省参数和显存；SFT/DPO 决定用什么监督信号。只有同一可见上下文下存在可靠的一好一差动作、SFT 后仍可复现错误，才试 DPO。GRPO 等有独立环境奖励、可重复 rollout 且有算力预算后再评估。每次登记模型、数据、种子、训练 token、GPU 时和成品回归，另查旧工具调用任务的遗忘。租 GPU 和启动年报训练需要单独决策。
5. **试用与复用。** 请分析师完成一次初稿审阅和下一期报告修订，记录每份委托的人审分钟、人工改数次数、错发或重复收件和复用后遗留的旧数。历史实验、脚本操作、本人试用和独立用户试用分别汇报；真实试用是评价节省工时和产品体验的依据。

面试演示从 D16 历史错答开始，回到 PDF 原页，切换到 D17/D18 查看正确、退化和残留案例，再打开上游收件及 D19 盲评表。接受追问时能复算分母、指出哪一条证据来自哪里，即已具备第一阶段的演示条件。独立标注、跨文档锁测、模型权重提升和实际人审节省工时各自有单独验收。
